# Optional git patches (go-googlesql protobuf)

Committed **`*.patch`** files here are applied **in sorted filename order** after
[`ApplyProtobufAmalgamationPatches`](../../../vendorpatch/amalgamation.go) when you run:

- `go run ./internal/cmd/vendorpatch` (repository root), or
- [`scripts/apply-vendor-patches.sh`](../../../../scripts/apply-vendor-patches.sh)

**Requirements:** `git` on `PATH`. Patches must be unified diffs with paths **relative to the repository root** (e.g. `internal/ccall/protobuf/google/protobuf/extension_set.cc`, or GoogleSQL embed paths such as `internal/ccall/zetasql/public/error_helpers.cc`). Prefer numeric prefixes so order is explicit (`01-foo.patch`, `02-bar.patch`).

## `01-vendor-delta.patch`

This file captures **all** go-googlesql–specific edits under `internal/ccall/protobuf/google/protobuf/` beyond what upstream protobuf and amalgamation (`port_def.inc` / `port_undef.inc`) already provide. It is generated by diffing:

1. **Baseline:** `com_google_protobuf` from [`internal/cmd/updater/cache/external/`](../../../cmd/updater/cache/external/) copied into a temp tree, then **amalgamation only** (`go run ./internal/cmd/vendorpatch -ccall … -amalgamation-only`).
2. **Current:** the committed vendored tree.

**Regenerate** (after you change vendored files or refresh the cache to match a new protobuf pin):

```bash
./scripts/gen-protobuf-vendor-patches.sh
```

The script writes `.genpatch-baseline/` under the repo root (listed in `.gitignore`), prints a one-line validation command, and overwrites `01-vendor-delta.patch`. Re-run `go test ./internal/vendorpatch/...` and a CGO build as in `docs/protobuf-vendoring.md`.

**Idempotency:** `vendorpatch` applies git patches only when forward-apply is possible; if the tree already matches the post-patch state (typical dev checkout), it detects that with `git apply --reverse --check` and skips—so you can run `go run ./internal/cmd/vendorpatch` repeatedly.

## `02-zetasql-cgo-status-payload.patch`

CGO-specific hardening for **status payloads** when protobuf descriptors are not initialized in every amalgamation shard: `zetasql/base/status_payload.h`, `zetasql/common/status_payload_utils.h`, and `zetasql/public/error_helpers.cc` under [`internal/ccall/zetasql/`](../../zetasql/). See [`docs/zetasql-submodule-policy.md`](../../../../docs/zetasql-submodule-policy.md) — do **not** cherry-pick these edits into the upstream submodule; keep the submodule at a release tag and apply this patch after the updater copies sources into `internal/ccall/zetasql/`.

**Regenerate** after a GoogleSQL tag bump (baseline = files under [`internal/cmd/updater/zetasql`](../../../cmd/updater/zetasql) at the tag, current = committed `internal/ccall/zetasql/`):

```bash
repo=/path/to/go-googlesql
u="$repo/internal/cmd/updater/zetasql/zetasql"
c="$repo/internal/ccall/zetasql"
{
  git -C "$repo" diff --no-index "$u/base/status_payload.h" "$c/base/status_payload.h"
  git -C "$repo" diff --no-index "$u/common/status_payload_utils.h" "$c/common/status_payload_utils.h"
  git -C "$repo" diff --no-index "$u/public/error_helpers.cc" "$c/public/error_helpers.cc"
} | sed -e '/^index /d' -e '/^old mode/d' -e '/^new mode/d' \
  -e 's#^diff --git a/internal/cmd/updater/zetasql/zetasql/#diff --git a/internal/ccall/zetasql/#g' \
  -e 's#--- a/internal/cmd/updater/zetasql/zetasql/#--- a/internal/ccall/zetasql/#g' \
  > "$repo/internal/ccall/protobuf/patches/02-zetasql-cgo-status-payload.patch"
# Then: git apply --reverse --check internal/ccall/protobuf/patches/02-zetasql-cgo-status-payload.patch
```

## Manual patch slices

If `git apply` fails after an upstream refresh, you can replace hunks by hand or recreate a smaller patch, e.g.:

```bash
git diff -- internal/ccall/protobuf/path/to/file.cc > internal/ccall/protobuf/patches/02-name.patch
```

Or drop a patch if the fix landed upstream. See [docs/protobuf-vendoring.md](../../../../docs/protobuf-vendoring.md).
